# Закрытая аналитика по адресу /analytics

После публикации откройте `/analytics` на домене лендинга. На странице входа заполните поля «Логин» и «Пароль» и нажмите «Войти». Таблица читает уже собранные данные Vercel Web Analytics; отдельная база и повторная отправка событий не нужны.

## Настройка Vercel

1. В проекте Vercel включите **Analytics → Enable**. Для пользовательских событий используется ваш Pro / Enterprise.
2. В **Settings → Environment Variables** добавьте переменные из таблицы ниже для **Production**. Если нужен закрытый раздел на тестовых адресах, добавьте их и для **Preview**.
3. Выполните новый deployment: изменения переменных применяются к новым публикациям. Корневая папка должна содержать `vercel.json`, `api/`, `server/`, `scripts/` и файлы лендинга. Framework Preset — **Other**; сборка и Output Directory уже указаны в `vercel.json`.
4. Откройте `https://ВАШ-ДОМЕН/analytics` и введите выбранные учётные данные. По умолчанию логин `admin`; пароль вы задаёте сами.

| Переменная | Что указать |
| --- | --- |
| `ANALYTICS_PASSWORD` | Длинный уникальный пароль для входа. Обязателен; готового пароля в коде нет. Сохраните как Secret. |
| `ANALYTICS_USERNAME` | Ваш логин. Если не задан, используется `admin`. |
| `VERCEL_ANALYTICS_TOKEN` | Vercel Access Token с доступом к проекту и его команде. Сохраните как Secret. Это не ключ Supabase. |
| `VERCEL_ANALYTICS_PROJECT_ID` | ID этого проекта Vercel из его настроек. Если не задан, сервер использует системный `VERCEL_PROJECT_ID`, когда он доступен. |
| `VERCEL_ANALYTICS_TEAM_ID` | ID команды, которой принадлежит проект. Для проекта личного аккаунта оставьте пустым. |

Пустой [.env.example](.env.example) содержит только названия и логин `admin`. Секреты задаются в Vercel; не добавляйте их в `config.js` или другие файлы браузера.

Список требований к чтению отчётов опубликован в [Web Analytics API](https://vercel.com/docs/analytics/web-analytics-api). Управление переменными и применение их к новым deployment описаны в [Environment Variables](https://vercel.com/docs/environment-variables).

## Что показывает таблица

- **Экраны:** просмотры, уникальные посетители внутри каждого экрана, клики основной кнопки, доля кликов, среднее и суммарное видимое время.
- **Выбор собеседника:** Women / Men / Both. «Выборы» — явные действия с карточками. «Подтверждения» — вариант, с которым нажали основную кнопку второго экрана, включая принятие исходного выбора.
- **Типаж:** Karolina / Hanna / Helen / Laura; отдельно явные выборы и подтверждение основной кнопкой четвёртого экрана.
- **Почта и переходы:** три этапа — корректно заполненная почта, валидная отправка формы и запуск перехода по ссылке Supabase. Для каждого показаны события и уникальные посетители; доля переходов считается по событиям как переходы / отправки.
- **География:** страны, просмотры и уникальные посетители. Эта таблица показывает все страны за период и выбранную версию сайта; фильтр страны применяется к экранам и событиям, чтобы варианты стран оставались доступны.
- **Распределение времени:** количество записанных отрезков в диапазонах `<5s`, `5-15s`, `15-30s`, `30-60s`, `1-2m`, `>=2m`.

По умолчанию выбран основной сайт и последние семь дней. Можно изменить даты, страну и версию сайта, затем нажать «Обновить». Даты включены целиком и считаются по UTC; один запрос охватывает до 31 дня. Доступность исторических данных зависит от периода хранения в вашем тарифе Vercel.

Клики и выборы считаются как события. Повторные действия одного посетителя увеличивают счётчик. Доля кликов — клики / просмотры, поэтому при повторных попытках отправки формы она может превышать 100%. Уникальных посетителей разных экранов нельзя складывать как общее число людей.

Время в фоне исключено. Среднее на экране рассчитывается как сумма записанного видимого времени / просмотры этого экрана. Статистика времени появляется после отправки завершённого отрезка; для ещё открытого экрана отрезок может быть не записан.

API Vercel ограничивает число отдельных групп и объединяет остаток в `Others`. Если это произошло со значениями `duration_ms`, точную сумму и среднее восстановить нельзя: таблица показывает «Неполные данные», раскрывает распределение по диапазонам и выводит предупреждение. При ошибке API показывается ошибка; существующие данные остаются помеченными как результат предыдущего запроса.

## Как считаются почта и переходы

| Этап в таблице | Событие Vercel | Когда учитывается |
| --- | --- | --- |
| Ввели корректную почту | `email_entered` | Один раз за загрузку страницы после ввода адреса в корректном формате. Валидная отправка с автозаполненным адресом также фиксирует этап, если он ещё не был записан. |
| Отправили форму с почтой | `email_submit` | Каждая валидная попытка, включая повторную отправку после ошибки. Невалидный адрес и повторное нажатие во время выполняющегося запроса не учитываются. |
| Перешли по ссылке Supabase | `outbound_redirect` | После выполнения `location.assign` без исключения для актуальной попытки, если переход не отменён. Ошибки и устаревшие или отменённые попытки не учитываются. |

Последний этап означает запуск перехода браузером, а не подтверждение загрузки внешнего сайта. «Доля переходов» — число событий `outbound_redirect` / число событий `email_submit`; при отсутствии отправок показано «—». Это отношение событий за выбранный период, а не доля уникальных людей. Посетители считаются Vercel отдельно для каждого этапа, и складывать их нельзя.

В этих событиях передаётся только номер пятого экрана. Сам email, параметры итоговой ссылки и её URL не записываются в аналитику и не возвращаются в отчёте. Данные новых этапов начнут собираться после публикации версии с этими событиями. Старые посещения не восстановлены, поэтому за периоды до этой публикации строки могут показывать нули.

## Как закрыт доступ

`/analytics`, `/analytics/` и `/api/analytics` обслуживает одна серверная функция. Без входа она выдаёт только форму; запрос данных возвращает 401. Форма отправляет логин и пароль методом POST на тот же сайт, сервер проверяет их и создаёт подписанную сессию на 8 часов. Неверные данные показывают ошибку рядом с полями, всплывающее окно браузера не используется. Без пароля в окружении раздел закрыт с ответом 503. Запросы не кешируются, страница исключена из индексации и не встраивается в iframe. Ссылок на неё в лендинге нет.

На странице входа и в таблице заголовок и HTML-метатег `Referrer-Policy` используют `same-origin`: обычные POST-формы входа и выхода сохраняют источник запроса для проверки сервером, а внешним сайтам referrer не передаётся. `no-referrer` здесь использовать нельзя: браузер может отправить `Origin: null`, и сервер отклонит форму с `INVALID_ORIGIN`.

Шаблоны `server/analytics-login.html` и `server/analytics-dashboard.html` находятся вне публичной папки. Сборка копирует в `public` только шесть файлов лендинга и разрешённые медиа; серверный код, документация и `.env` туда не попадают. Пароль и токен никогда не возвращаются в HTML или JSON. Сам раздел не отправляет события аналитики.

Сессия хранится в cookie с `HttpOnly`, `Secure`, `SameSite=Lax` и префиксом `__Host-`; JavaScript не читает её. POST входа и выхода принимается только с того же origin. Кнопка «Выйти» очищает cookie в этом браузере, истёкшая сессия возвращает на форму. Поля поддерживают автозаполнение менеджером паролей; пароль в URL и localStorage не записывается. Форма работает без JavaScript.

Смена пароля или логина требует нового deployment и делает прежние подписи сессий недействительными в нём. Старые опубликованные адреса имеют собственные настройки того deployment, поэтому их нужно удалить, если требуется отозвать старый доступ. На чужом компьютере нажмите «Выйти» после просмотра.

## Проверка после публикации

Откройте `/analytics` в приватном окне: должны быть видны два поля входа, таблица недоступна. Убедитесь, что прямой `/api/analytics?data=1` отвечает 401 без сессии, а `/server/analytics-dashboard.html` и `/server/analytics-login.html` не выдают файлы. Затем войдите, проверьте обновление страницы и кнопку «Выйти». Пройдите опубликованный лендинг и обновите отчёт после обработки событий Vercel. Сравните показатели с вкладкой Analytics этого же проекта и периода.

Если появляется «Доступ к данным ещё не настроен», проверьте переменные токена и Project ID. При отказе Vercel проверьте доступ токена и Team ID. Не передавайте пароль или токен в URL.
